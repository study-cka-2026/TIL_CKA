## 100. Rolling Updates and Rollbacks

컨테이너 버전이 새 버전으로 업데이트되면 새 rollout이 트리거됨 <br>
새 rollout은 새 replicaset을 생성하며, 추후 애플리케이션이 업그레이드될 때 새 배포 리비전으로 기록됨 <br>
이를 통해 배포에 대한 변경 사항을 추적하고 필요한 경우 이전 버전의 배포로 롤백할 수 있음

`kubectl rollout status deployment/myapp-deployment`으로 롤아웃 상태 확인 가능 <br>
`kubectl rollout history deployment/myapp-deployment`으로 롤아웃의 수정 버전과 이력 확인 가능

배포 전략에는 2가지가 있음
1. Recreate Strategy
    - 실행 중인 인스턴스를 삭제한 다음 새 애플리케이션 버전의 인스턴스를 배포함
    - 이전 버전이 다운된 후 새 버전이 올라가기 전까지 애플리케이션이 다운되어 사용자가 액세스할 수 없음
2. Rolling update (기본 배포 전략)
    - 이전 버전을 내리고 최신 버전을 하나씩 불러오는 방식으로 인스턴스를 배포함
    - 애플리케이션이 다운되지 않고 원활하게 업그레이드 가능

<br>

업데이트는 애플리케이션 버전 업그레이드, 레이블 업데이트, 복제본 수 업데이트 등 다양한 것을 의미할 수 있음 <br>
[배포 정의 파일](/esc/2026-01-20/deployment-definition.yaml)을 이미 작성했으므로 수정 사항을 저장하고 `kubectl apply -f deployment-definition.yaml` 명령어를 실행하면 새 롤아웃이 트리거되고 배포 revision이 생성됨 <br>
`kubectl set image deployment/myapp-deployment nginx=nginx:1.9.1` 등의 명령어로 직접 이미지 버전을 바꿀 수 있지만 배포 파일의 구성과 달라지므로 주의해야 함 <br>
배포 진행 중 `kubectl get replicasets` 명령어를 입력하면 이전 replicaset에서 새 replicaset으로 rollling update가 되고 있는 것을 알 수 있음<br>
롤백의 경우 `kubectl rollout undo deployment myapp-deployment` 명령어를 이용해 실행 가능함

## 104. Commands and Arguments in Docker

`docker run ubuntu` 명령을 실행하면 ubuntu 이미지 인스턴스가 실행되고 즉시 종료됨<br>
가상 머신과 달리 컨테이너는 운영 체제를 호스팅하기 위한 것이 아니기 때문임.<br>
컨테이너는 웹 서버나 애플리케이션 서버, 데이터베이스의 인스턴스를 호스팅하거나 계산이나 분석을 수행하는 등 특정 작업이나 프로세스를 실행하기 위한 것이므로 작업이 완료되면 컨테이너가 종료됨<br>
컨테이너 내부의 웹 서비스가 중지되거나 충돌이 발생하면 컨테이너가 종료됨

컨테이너 내에서 어떤 프로세스가 실행되는지는 Dockerfile에서 CMD 명령어로 컨테이너 내에서 실행될 프로그램을 정의하고 있음<br>
일반 ubuntu 이미지의 컨테이너를 실행하면 `CMD ["bash"]`가 실행되는데, bash는 프로세스가 아니라 터미널에서 입력을 수신하는 셸이므로 터미널을 찾을 수 없으면 종료됨<br>
따라서 ubuntu 컨테이너를 실행했을 때 docker는 ubuntu 이미지에서 컨테이너를 실행하고 bash 프로그램을 실행했으나, docker는 기본적으로 컨테이너를 실행할 때 터미널을 컨테이너에 연결하지 않기 때문에 bash 프로그램이 터미널을 찾지 못해 종료됨<br>
컨테이너가 생성될 때 시작된 프로세스가 완료되었으므로 컨테이너도 종료됨

도커 실행 명령에 명령을 추가해 이미지 내에 지정된 기본 명령을 재정의해 이 문제를 해결할 수 있음<br>
`docker run ubuntu sleep 5` 명령어를 실행하면 컨테이너가 시작된 후 5초 동안 sleep한 뒤 종료됨<br>
이미지가 시작될 때 항상 sleep 명령을 실행하려고 한다면 `FROM Ubuntu CMD["sleep", "5"]` 방식으로 Dockerfile을 저장한 뒤 `docker build -t ubuntu-sleeper .`로 이미지를 생성하고, 이 이미지로 `docker run ubuntu-sleeper`처럼 실행하면 동일한 결과를 얻을 수 있음

그렇다면 `docker run ubuntu-sleeper 10`처럼 sleep의 시간을 매개변수로 입력받으려면 어떻게 할 수 있을까?<br>
`FROM Ubuntu ENTRYPOINT["sleep"]`처럼 작성하면 됨<br>
entrypoint는 실행 명령을 정의함. 컨테이너가 시작될 때 실행할 프로그램과 명령줄에서 지정하는 모든 것을 entrypoint로 지정할 수 있음<br>
cmd 명령어의 경우 전달된 명령줄 매개변수가 완전히 대체되는 반면, entrypoint의 경우 명령줄 매개변수가 추가됨

그렇다면 명령줄에 기본값이 지정되지 않은 경우 명령의 기본값은 어떻게 구성할 수 있을까?<br>
`FROM Ubuntu ENTRYPOINT["sleep"] CMD["5"]`처럼 입력하면 명령줄에 매개변수를 지정하지 않는 경우 CMD에 작성된 값이 사용되고, 매개변수를 입력받으면 그 값으로 덮어씌워짐<br>
런타임 중 entrypoint에서 sleep → sleep2.0으로 변경하고 싶은 경우 `docker run --entrypoint sleep2.0 ubuntu-sleeper 10` 명령을 입력하면 entrypoint는 sleep → sleep2.0으로 덮어씌워지고, 매개변수는 입력받은 10이 사용됨
