## 145. Backup and Restore Methods

클러스터에서 리소스는 create 명령어를 이용해서 만들거나, 정의 파일을 생성한 다음 apply를 통해 만들어짐<br>
단일 애플리케이션에 필요한 모든 개체를 단일 폴더에 개체 정의 파일 형태로 저장할 수 있으므로 구성을 저장하는 경우 정의 파일을 선호함<br>
정의 파일의 경우 Github과 같은 소스 코드 저장소에 저장하는 것이 좋음

명령형 개체까지 백업하기 위해서는 kubectl을 사용하거나 API 서버에 직접 액세스해야 함<br>
kube-apiserver를 쿼리하고 클러스터에 생성된 모든 개체에 대한 모든 리소스 구성을 복사본으로 저장할 수 있음<br>
`kubectl get all --all-namespaces -o yaml > app-deploy-services.yaml`같은 명령어로 yaml 파일로 추출해 저장할 수 있음<br>
혹은 velero 등의 도구를 이용해 kubernetes cluster를 백업할 수 있음

etcd 클러스터는 클러스터 자체, 노드 및 클러스터 내에서 생성된 기타 모든 리소스에 대한 정보를 저장됨<br>
따라서 리소스를 백업하는 대신 etcd 서버 자체를 백업할 수 있음<br>
etcd.server 명령어에서 --data-dir 경로가 백업 도구에서 백업하도록 구성할 수 있는 디렉터리임<br>
etcd에는 스냅샷 솔루션이 있으므로 `etcdctl snapshot save snapshot.db`로 백업을 생성할 수 있음<br>
`etcdctl snapshot status snapshot.db` 명령어로 백업 파일의 상태를 확인할 수 있음<br>
백업에서 클러스터를 복원하려면 `systemctl stop kube-apiserver`로 etcd 클러스터를 재시작하기 전 api 서버를 멈춘 다음 `etcdctl snapshot restore snapshot.db --data-dor /var/lib/etcd-fron-backup` 명령어로 백업 파일에서 복원하도록 함<br>
etcd가 백업에서 복원하면 새 클러스터 구성을 초기화하고 etcd의 멤버를 새 클러스터의 새 멤버로 구성됨<br>
그 뒤 멈췄던 서비스들을 다시 시작함
```
systemctl daemon-reload
systemctl restart etcd
systemctl start kube-apiserver
```

모든 etcd 명령을 사용하기 전 인증을 위한 인증서 파일을 지정해야 함<br>
etcd 클러스터와 인증서, 서버 인증서 및 키에 대한 엔드포인트를 지정해야 etcdctl을 사용할 수 있음<br>
관리형 kubernetes 환경을 사용하는 경우 etcd 클러스터에 액세스하지 못하는 경우가 있을 수 있는데, 이때 kube-apiserver를 쿼리해 백업하는 것이 필요할 수 있음
