## 61. Node Selectors

노드의 용량이 동일하지 않을 때, 처리량이 많은 작업은 특정 노드에서만 실행되도록 파드에 제한을 설정할 수 있음<br>
Node Selectors 사용: Node에 size=large 레이블 할당 후 [pod.yaml](/esc/2026-01-10/pod.yaml) 작성<br>
노드에 레이블은 `kubectl label nodes <node-name> <label-key>=<label-value>`로 지정 가능함<br>
Node Selector는 단일 레이블과 선택기만 사용할 수 있음. 따라서 더 복잡한 요구사항을 위해서 Node Affinity를 사용함

## 62. Node Affinity

Node Affinity 목적: 특정 노드에 대한 파드 배치를 제한하는 고급 기능 제공<br>
OR 혹은 Not 등의 복잡한 요구사항을 표현하기 위해서 Node Selector 대신 Node Affinity를 사용함

spec → affinity → x → requiredDuringSchedulingIgnoredDuringExecution<br>
nodeSelectorTerms에서 배치를 원하는 key-value 쌍을 입력함<br>
[pode-affinity.yaml](/esc/2026-01-10/pod-affinity.yaml)의 경우 size 레이블 값이 Large 혹은 Medium인 노드에만 파드를 배치한다는 의미<br>
operator에는 In, NotIn, Exists(해당 레이블이 있는 노드, 값 비교 X) 등이 있음

nodeAffinity type은 nodeAffinity와 관련된 스케줄러의 동작과 파드 수명주기의 단계를 정의함<br>
파드의 라이프사이클(DuringScheduling, DuringExecution)에 따라 달라짐
- DuringScheduling: 파드가 존재하지 않고 처음 생성될 때 지정된 nodeAffinity가 올바른 노드에 파드를 배치함
- DuringExecution: 파드가 실행 중인 상태
- requiredDuringSchedulingIgnoredDuringExecution: nodeAffinity를 찾지 못하면 파드 예약 X, 파드 배치가 중요한 경우 사용됨, 실행 중 nodeAffinity가 달라져도 파드 영향 X
- preferredDuringSchedulingIgnoreDuringExecution: nodeAffinity를 찾지 못하면 사용 가능한 모든 노드에 배치, 실행 중 nodeAffinity가 달라져도 파드 영향 X

## 65. Taints and Tolerations vs Node Affinity

- Taints and Tolerations:
    - toleration을 가진 파드만 노드에 배치될 수 있도록 함
    - 하지만 독점적인 배치를 보장하지 않으므로 taint가 설정되지 않은 다른 노드에 배치 가능함
- Node Affinity:
    - node selector에 따라 올바른 노드에 파드가 배치됨
    - 하지만 다른 파드가 해당 노드에 배치되는 것을 막지 못함

Taints and Tolerations, Node Affinity를 함께 사용할 때 가장 효과적임

## 66. Resource Limits

kube-scheduler는 파드에 필요한 리소스의 양과 노드에서 사용 가능한 리소스를 고려하여 파드를 배치하기에 가장 적합한 노드를 식별함
노드에 사용 가능한 리소스가 충분하지 않은 경우, 스케줄러는 충분한 리소스를 사용할 수 있는 노드에 파드를 배치함
어떤 노드에도 충분한 리소스가 없으면 스케줄러가 파드를 보류 상태로 둠

파드를 생성할 때 파드에 필요한 CPU와 메모리의 양을 지정할 수 있음 = 컨테이너에 대한 리소스 요청
스케줄러가 노드에 파드를 배치하려고 할 때, 리소스 요청보다 자원이 남아 있는 노드를 식별하여 배치함
[pod-resources.yaml](/esc/2026-01-10/pod-resources.yaml)처럼 작성해 파드를 생성하고 노드에 배치되면 파드는 사용할 수 있는 리소스의 양을 보장받음
CPU 1개는 1 vCPU(= CPU Core)를 의미하며, 메모리는 Mi(Mebibyte= 1024MB), Gi(Gigibyte), M(Megabyte), G(Gigabute) 등의 단위로 나타냄

파드에서 리소스 사용량에 대한 제한을 설정할 수 있음
[pod-resources.yaml](/esc/2026-01-10/pod-resources.yaml)의 limits처럼 각 컨테이너의 리소스 제한을 설정할 수 있음
파드가 지정된 CPU 한도를 초과하여 리소스를 사용하려고 하면 한도를 초과하지 못하도록 시스템에서 리소스를 throttle하지만, 메모리는 한도를 강제할 수 없으며 메모리 초과 시 terminate됨
기본적으로 쿠버네티스는 CPU 또는 메모리 요청이나 제한이 설정되어 있지 않음
일반적으로 CPU는 requests, no limits가 가장 이상적인 설정임
namespace에서 [LimitRange](/esc/2026-01-10/limit-range.yaml)를 설정하면 모든 파드에 CPU와 메모리 리소스 기본값을 설정할 수 있음
쿠버네티스 클러스터에 배포된 애플리케이션이 사용할 수 있는 총 리소스 양을 제한하려면 네임스페이스 수준에서 [ResourcQuotas](/esc/2026-01-10/resource-quotas.yaml)를 설정할 수 있음
