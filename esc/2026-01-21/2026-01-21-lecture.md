## 109. Configuring ConfigMaps in Applications

environment 데이터를 파드 정의 파일에서 가져와서 configmap을 이용해 중앙에서 관리할 수 있음<br>
ConfigMap은 쿠버네티스에서 키-값 쌍의 형태로 구성 데이터를 전달하는 데 사용됨<br>
파드가 생성되면, 키-값 쌍을 파드의 컨테이너 내부에서 호스팅되는 애플리케이션의 환경 변수로 사용할 수 있도록 ConfigMap을 [pod.yaml](/esc/2026-01-21/pod-definition-configmap.yaml)에 추가함<br>
명령형 방식으로 사용하면 `kubectl create configmap <config-name> --from-literal=<key>=<value>`로 명령어를 사용해 주입하거나 `kubectl create configmap <config-name> --from-file=<path-to-file>`로 파일에서 불러올 수 있음<br>
선언형 방식으로 사용하면 [config-map.yaml](/esc/2026-01-21/config-map.yaml)를 작성한 뒤 `kubectl create -f config-map.yaml`로 적용하면 됨<br>
다양한 목적을 위해 같은 방식으로 필요한 만큼의 configmap을 생성 가능하며 `kubectl get configmaps`로 불러올 수 있음<br>
ConfigMap은 env뿐만 아니라 단일 환경 변수로 삽입하거나 전체 데이터를 볼륨의 파일로 삽입할 수 있음 ([pod.yaml](/esc/2026-01-21/pod-definition-configmap.yaml) 참고)

## 112. Secrets

password 등 민감한 정보는 일반 텍스트 형식으로 저장되는 configmap이 아닌 인코딩 또는 해시 형식으로 저장되는 secret으로 저장해야 함<br>
명령적 방식은 `kubectl create secret generic <secret-name> --from-literal=<key>=<value`과 같이 명령어를 사용하는 방식이 있음<br>
명령어를 사용하지 않는다면 `kubectl create secret generic <secret-name> --from-file=<path-to-file>`로 파일을 생성할 수도 있음<br>
선언적 방식은 [secret.yaml](/esc/2026-01-21/secret.yaml)처럼 선언하되, 텍스트를 `echo -n 'mysql' | base64`처럼 변환해 저장해야 함

secret은 `kubectl describe secrets` 명령어를 입력하면 어떤 값을 가지고 있는지만 보이고, 내부 값을 보고 싶다면 `kubectl get secret app-secret -o yaml`로 출력해야 함<br>
해시값을 해독하기 위해서 `echo -n <base64> | base64 --decode` 명령어를 사용하면 됨<br>
[pod-secret.yaml](/esc/2026-01-21/pod-secret.yaml) 처럼 작성하면 파드에 secret을 주입할 수 있음<br>
볼륨으로 주입한 경우 `ls /opt/app-secret-volumes`로 검색하면 저장된 내용들을 확인할 수 있고, `cat /opt/app-secret-volumes/DB_Password`로 값을 출력할 수 있음

## 116. Demo: Encrypting Secret Data at Rest

[Demo: Encrypting Secret Data at Rest](https://kubernetes.io/docs/tasks/administer-cluster/encrypt-data/)

- secret 파일은 base64 --decode로 평문 변환할 수 있으니 github 등 공개된 공간에 올리지 않을 것
- etcd-client 설치 후 etcd 경로에 인증서가 있는지 확인하고 문서의 ETCDCTL_API 명령어 입력 → 암호화되지 않은 상태로 저장되는 것 확인 = etcd 접근 가능하면 secret 확인 가능
- `ps -aux | grep "encryption-provider-config"`가 활성화 되어 있는지 확인 → `cat /etc/kubernetes/manifest/kube-apiserver.yaml`을 보면 비활성화라서 암호화되어 저장되지 않음
- provider이 identity이면 암호화가 되지 않으므로 암호화 알고리즘 중 하나가 설정되어야 함
    - [enc.yaml](/esc/2026-01-21/enc.yaml)처럼 provider의 목록에서 identity를 맨 아래에 두고 위에 암호화 알고리즘과 키를 작성하면 해당 암호화 방식으로 secret 파일이 암호화됨
- kube-apiserver에서 --encryption-provider-config=/etc/kubernetes/enc/enc.yaml을 가리키고, enc를 내부에 마운트함
    - 로컬 디렉토리의 /etc/kubernetes/enc가 파드 내부의 /etc/kubernetes/enc 디렉토리에 매핑되고, 파드 내부의 enc.yaml 파일을 통해 암호화됨
- `crictl pods`로 kube-apiserver 파드가 재시작되고 secret 파일을 만들면 암호화가 적용된 것을 확인할 수 있음
