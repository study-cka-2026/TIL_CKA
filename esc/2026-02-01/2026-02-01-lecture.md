## 136. OS Upgrades

기본 소프트웨어를 업그레이드하거나 패치를 적용하는 등의 유지 관리 목적으로 클러스터의 일부인 노드를 제거해야 하는 시나리오를 가정함

노드가 다운되었을 때, 해당 노드에만 있는 파드가 있다면 사용자도 영향을 받을 수밖에 없음<br>
노드가 즉시 온라인 상태가 되면, kube-control 프로세스가 시작되고 파드가 다시 온라인 상태가 됨<br>
하지만 노드가 5분 이상 다운된 경우, 해당 노드에서 파드가 종료되고 ReplicaSet으로 설정된 경우 다른 노드에서 파드를 다시 실행함<br>
파드가 다시 온라인 상태가 될 때까지 기다리는 시간을 pod eviction timeout이라고 하고, 기본값은 5분임<br>
pod eviction timeout 이후 노드가 다시 온라인 상태가 되면 예약된 파드 없이 빈 노드로 표시됨

의도적으로 모든 워크로드의 노드를 `kubectl drain <node-name>`으로 노드를 비우고 재부팅함<br>
노드를 비우면 파드는 해당 노드에서 정상적으로 종료되고 다른 노드에서 다시 생성됨<br>
또한 이 노드는 제한되거나 예약 불가능으로 표시되어, 제한을 구체적으로 제거할 때까지 이 노드에 어떤 파드도 예약할 수 없음<br>
재부팅이 완료되면 파드를 다시 예약할 수 있도록 `kubectl uncordon <node-name>`으로 조정을 해제해야 함<br>
유사한 명령어로는 `kubectl cordon <node-name>`이 있는데, 노드를 종료하거나 이동하지 않지만 해당 노드가 스케줄되지 않도록 함

## 141. Cluster Upgrade Introduction

모든 요소가 동일한 버전을 사용할 필요는 없음<br>
kube-apiserver는 컨트롤 플레인의 기본 구성 요소이며 다른 모든 구성 요소와 통신하므로 다른 컴포넌트 중 어느 것도 kube-apiserver보다 높은 버전이면 안됨 - version x<br>
controller-manager와 kube-scheduler는 한 버전 아래에서 사용할 수 있음 - version (x-1)까지 가능<br>
kubelet과 kube-proxy는 controller보다 한 버전 아래까지 사용할 수 있음 - version (x-2)까지 가능<br>
kubectl은 kube-apiserver보다 1 버전까지 차이날 수 있음 - x+1 > version > x-1

kubernetes는 최신 버전으로부터 하위 2버전까지만 지원함<br>
ex) v1.13 릴리즈 > v1.13, v1.12, v1.11 사용 가능<br>
버전 업그레이드 시 한 번에 하나의 마이너 버전을 업그레이드하는 것을 추천함

업그레이드 프로세스는 클러스터 설정 방식에 따라 다름<br>
managed kubernetes cluster라면 관리 주체를 통해 편하게 업그레이드할 수 있고, kubeadm을 통해 설치했다면 upgrade plan과 apply를 통해 업그레이드가 가능함<br>
클러스터를 처음부터 배포한 경우에는 클러스터의 여러 구성 요소를 직접 수동을 업그레이드해야 함

클러스터를 업그레이드하는 데는 크게 두 가지 단계가 있음
1. 마스터 노드 업그레이드
    - API, 서버, 스케줄러, 컨트롤러 매니저와 같은 control plane 구성 요소는 잠시 다운되어 클러스터 작업이 불가능
    - 워커 노드와 애플리케이션은 영향 X > 사용자와 서비스에는 영향 X
    - 업그레이드가 완료되고 클러스터가 백업되면 정상적으로 작동함
2. 워커 노드 업그레이드
    - 한 번에 모두 업그레이드: 파드가 다운되고 사용자가 액세스가 불가능한 다운타임이 발생함
    - 한 번에 한 노드씩 업그레이드: OS Upgrades 랩처럼 다른 노드에 실행 중인 파드를 옮기고 업그레이드 진행
    - 최신 소프트웨어 버전: 클러스터 노드에 업그레이드 버전의 노드를 추가해 새로운 버전의 노드로 갈아끼움
        - 새 노드를 쉽게 프로비저닝하고 기존 노드를 폐기할 수 있는 클라우드 환경에서 추천

<br>

`kubeadm upgrade plan` 명령어를 통해 현재 버전과 업그레이드가 가능한 버전을 제공함<br>
클러스터를 업그레이드하려면 kubeadm 툴을 업그레이드 해야 함

```
apt-get upgrade -u kubeadm=1.12.0-00
kubeadm upgrade apply v1.12.0
```
완료되면 컨트롤 플레인 구성 요소의 버전이 v.1.12.0이 됨

```
apt-get upgrade -y kubelet=1.12.0-00
systemctl restart kubelet
```
마스터 노드에서 kubelet을 업그레이드함<br>
이 경우 master node에서 출력되는 version이 올라감<br>
왜냐하면 `kubectl get nodes`에 출력되는 version에는 API 서버 자체의 버전이 아니라 API 서버에 등록된 각 노드의 kubelet 버전이 표시되기 때문임

워커 노드에서 `kubectl drain node-1`으로 업그레이드 할 노드에서 실행 중인 파드를 다른 노드로 이동시킴
```
apt-get upgrade -y kubeadm=1.12.0-00
apt-get upgrade -y kubelet=1.12.0-00
kubeadm upgrade node config --kubelet-version v1.12.0
systemctl restart kubelet
kubectl uncordon node-1
```
명령어로 각 노드를 업그레이드하는 것을 반복함
